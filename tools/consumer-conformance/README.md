# Candidate producer / pinned consumer conformance

This Rust 1.97.1 CI-only tool compares candidate producer-library output with the exact reviewed
Console and Studio fixtures. It owns no runtime adapter and adds no product dependency.
Its manifest and lockfile are separate from the root workspace. Inputs must be clean consumer
checkouts at the exact revisions in `contracts/effective-limits-pins.json`; every inventoried
consumer artifact digest is verified before compilation.

```sh
cargo fmt --manifest-path tools/consumer-conformance/Cargo.toml -- --check
cargo clippy --locked --manifest-path tools/consumer-conformance/Cargo.toml --all-targets -- -D warnings
cargo test --locked --manifest-path tools/consumer-conformance/Cargo.toml
cargo run --locked --manifest-path tools/consumer-conformance/Cargo.toml -- \
  /absolute/candidate-harness /absolute/pinned-console /absolute/pinned-studio
```

The tool builds the candidate harness library using its root lockfile and captures Cargo's JSON
compiler artifacts in `target/consumer-conformance/`. It selects the unique non-test harness
artifact whose manifest belongs to that candidate and the unique `serde_json` library artifact
from that build. It never searches old build directories by glob.

Pinned `rustc` compiles the unchanged Console-owned
`tools/effective-limit-fixtures/src/main.rs` directly against those libraries. That original
generator uses only public harness memory/session library APIs and `serde_json`; its separate
Cargo manifest normally pins historical producer `f8015e52`. The candidate lane deliberately
does not invoke or alter that manifest, lockfile, generator source, golden fixture or consumer
tests. No generator implementation is copied into this repository.

Generated bytes must equal both consumer goldens byte-for-byte. Any change stops the lane before
the unchanged Console route/admission and Studio effective-limit tests run. Equality proves those
tests receive exactly the candidate-produced bytes; it does not substitute for running the tests.
Consumer and candidate identities are checked again after generation to catch changes during
the run.

`evidence.json` records the actual candidate revision, dirty state/diff and untracked source
digests, exact clean consumer revisions, compiler version, selected link artifacts and hashes,
generator source/binary hashes and generated-byte hash. Its result covers generation/equality
only; the following CI steps supply consumer-test status. The generator's embedded
`producer_revision: f8015e52...` is the **golden origin**, never evidence of which producer was
compiled in this run. `candidate-output.json` is a disposable diagnostic, not a newly published
fixture attributed to that historical commit.

All data is original synthetic fixture data. No provider, native peer, game, private capture,
owner transport or deployment is exercised. The separate Studio workflow-owner browser lane
retains its own authenticated process evidence and does not prove Context owner integration.

Coverage is the memory/session descriptor and record fixture surface. The separate management
context-control limits (items, notes, context/objective bytes and control events) remain outside
this lane. Scalar ceiling admission is not full policy validation: zero can be below a policy
minimum, and results/candidates or other relational constraints still require the policy
validator. The complete public-limit inventory, saved-policy persistence/adoption and composed
owner integration remain broader harness #95 work; no fixture result closes those gates.
